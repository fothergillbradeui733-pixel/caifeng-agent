## 1. 判定顺序

对每个空间词按以下顺序判断：

1. 原文是否明确写出？是则登记为原文事实并摘录最短证据。
2. 是否只是站、坐、跪、蹲、躺等基础姿态？是则允许补全，依据写“可拍化姿态补全”。
3. 是否属于左右、前后、远近、朝向或视线？没有原文依据时不得写成剧情空间。
4. 构图是否必须确定画左/画右？是则登记为银幕约定，不得写入原文依据。
5. 是否改变人物位置？是则必须生成移动事件并更新 Block 结束状态。摄影机运动不算人物位置变化。

原文证据优先于镜头美感；银幕约定只解决拍摄方向，不改变剧情事实。

## 2. 空间台账结构

内部空间工序输出一个 JSON 对象：

```json
{
  "screenDirectionConventions": [
    {
      "scene": "@病房",
      "rule": "@林晚恒画左，@秦墨恒画右",
      "basis": "银幕约定",
      "until": "场景结束或重新建场"
    }
  ],
  "blocks": [
    {
      "blockId": "Block 1",
      "scene": "@病房（日）",
      "cameraVisibleSubjects": ["@林晚", "@秦墨"],
      "offCameraState": [],
      "startState": [
        {"role": "@林晚", "state": "坐在病床边，攥着病历", "basis": "原文：坐在病床边"},
        {"role": "@秦墨", "state": "站在病房门口", "basis": "可拍化姿态补全；原文：出现在门口"}
      ],
      "moves": [
        {"role": "@秦墨", "from": "病房门口", "to": "窗前", "basis": "原文：秦墨走到窗前"}
      ],
      "endState": [
        {"role": "@林晚", "state": "坐在病床边，攥着病历"},
        {"role": "@秦墨", "state": "站在窗前"}
      ]
    }
  ],
  "episodeEndSnapshot": {
    "scene": "@病房",
    "continuation": "直续",
    "characters": []
  }
}
```

只记录剧本中真实存在的 Block。禁止创建 G1/G2 或在 Block 外再包一层分组。

## 3. 镜头可见主体与离画连续性

- `startState` 与 `endState` 是内部空间台账，跟踪场景内全部角色；`cameraVisibleSubjects` 只列当前 Block 被摄影机拍到的角色主体。
- `offCameraState` 保存仍在场景内但当前未入画的角色最后位置、姿态、持物、伤势和离画原因。场景存在不等于镜头可见。
- 交付正文的 `👤 出场` 与 `🧭 起始空间状态` 都只列 `cameraVisibleSubjects`。道具、屏幕、伤口、地点、家具和 UI 不属于角色主体。
- 横竖屏人数范围是建议值，不是硬上限。群像是否同框由剧情动作、构图层次和生成风险共同决定，不能只按人数判定失败或强制拆 Block。
- 只承担环境氛围的背景龙套、路人、宾客、士兵和背景人群不逐个进入 `cameraVisibleSubjects`；出现台词、关键动作、道具交互或推动剧情时才升级为角色主体并进入空间台账。
- 离开画面不等于离开场景。角色从画内转为画外时，更新 `offCameraState`；再次入画时，先表现可见入画动作、摄影机转向/重构图或明确时空切换。
- 横竖屏的主体建议范围见本技能 SKILL.md（竖屏 1–3 / 横屏 2–4 / 3D 横屏 2–5）；本合同负责保留未入画角色的连续性，且不设置人数硬审上限。

## 4. Block 状态传递

- Block 内部起始状态是本 Block 第一帧可见或仍需在画外追踪的空间事实；公开 `🧭 起始空间状态` 仅写本 Block 镜头可见角色主体。
- Block 结束状态等于起始状态应用全部移动、进入、离开、起身、坐下、倒地等变化后的结果。
- 同场景相邻 Block：`后一 Block.startState = 前一 Block.endState`，除非开头先明确表现新的移动。
- 换场：重新建立起始状态，不把旧场景的方位锚直接搬入新场景。
- 插入回忆、手机画面或监控画面时，标清临时视觉层；返回主场景后恢复主场景状态。

空间变化不会产生“子组”。内容超过单个 Block 的时长或生成复杂度时，创建下一个 Block，并让新 Block 继承前一个 Block 的结束状态。

Block 结束状态只保存在内部台账。交付正文不增加 `落幅锚点` 或无法验证的尾帧继承宣言；下一 Block 直接输出经过审核后的 `🧭 起始空间状态`。

摄影机推进、拉远、横摇、升降、环绕、焦点变化和手持晃动不更新人物位置。跟拍只有在画面描述同时写出人物 `从 A 到 B` 时才更新路径结果。景别和镜头角度也不能作为人物远近、高低或相对站位的证据。

## 5. 移动与离场

移动事件使用：

```text
@角色：从 {起点} 到 {终点}，{必要动作}
```

禁止：

```text
@秦墨来到窗前。
```

推荐：

```text
@秦墨从病房门口走到窗前，在窗前停下。
```

没有原文依据时，不增加路径经过的家具、人物或方向。人物离场写入结束状态：

```text
@秦墨(已离场→医院走廊)
```

重新入场时必须有入场动作或明确时空切换。

人物只离开当前画面、但没有离开场景时，不写“已离场”；应转入 `offCameraState`，保留其场内位置和状态。

## 6. 银幕约定与防越轴

银幕约定使用屏幕坐标，不冒充故事空间：

```text
银幕约定：@母亲恒画左，@女儿恒画右；对话轴线不翻面。
```

检查：

- 正反打双方是否保持相反视线方向。
- 追逐主体的屏幕运动方向是否稳定。
- 攻击方向 A→B 与受击反馈方向是否一致。
- 人物改变相对位置时，是否先拍到移动或重新建场。
- 跨 Block 边界是否沿用上一 Block 的最后位置与屏幕方向。

需要换边时，至少使用一种可见过渡：人物穿越轴线、摄影机连续越轴、正面中性镜头、全景重新建立。

## 7. 集尾快照

逐角色保存：

```text
@角色｜姿态｜所在位置｜朝向/视线（有依据时）｜持物｜伤势/外观｜离场去向
```

另存：

- 所在场景；
- 未闭合空间事实；
- 下集开场判定：直续或跳跃；
- 跳跃依据。

直续时，下一集首个 Block 必须逐维继承；跳跃时按新场景重新建立。

## 8. 完整示例

原文：

```text
林晚坐在病床边。秦墨出现在门口，沉默片刻，走到窗前。
```

Block 起点：

```text
🧭 起始空间状态：@林晚(坐在病床边)｜@秦墨(站在病房门口)
```

镜头动作（新格式：镜头行+正文，无"画面描述："标签）：

```text
🎬 镜头 2【秦墨 中景 缓慢跟拍】
@秦墨在病房门口停住，随后从病房门口走到窗前；@林晚仍坐在病床边。
```

Block 结束状态只写入内部台账：

```text
@林晚(坐在病床边)｜@秦墨(站在窗前)
```

原文没有写两人互看，也没有写病床左右，因此不得增加“面向林晚”“病床右侧”。如果正反打必须固定方向，可另登记银幕约定。
