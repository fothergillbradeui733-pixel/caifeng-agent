# 拆解执行卡 V6

本卡只负责把原文章节编译为结构化剧情地图。模式边界以 `fidelity-free-mode.md` 为准，机器门禁以`map-preflight`为准，质检范围以quality Plan及其checker brief为准。

默认每批6章。完整读取并校验原文后建立map-spec；任一章小于500B、缺号或含占位符时停止本批，不能用后文推断。

## MAP-SPEC

每个候选事件至少登记：

```text
source_anchor: 第X章｜邻近关键词/短引
event_id: 批次内及全项目稳定唯一事件ID
event: 发生了什么
actor: 谁主动做
receiver: 谁承受/响应
cause: 直接触发
result: 可观察结果/代价
knowledge_before: 各关键角色此前知道什么
knowledge_after: 谁在何时新知道什么
must_keep: 名台词/名场面/笑点/关键动作
adaptation: 保留/压缩/并场/删除及理由
episode_exit: 完成态或悬念问题
source_time_anchor: 原著时间原话所在章/关键词
source_relative_time: 当日/次日/七日后/半个月后/未明示（原样，不换算绝对日期）
pre_state: 事件前人物/道具/设定状态
completed_state: 事件完成后的可观察状态
reveal_boundary: 此刻允许观众与角色知道/看见到哪里
visual_candidates: 人物/物理空间/关键道具事实
visual_deltas: 新实体或颜色/形态/伤势/换装/易主/损毁/显露变化；无则写无
ledger_candidates: 伏笔/期限/行动线/口径
```

原著矛盾不得擅自抹平；登记取舍依据。任何角色合并、事件移位或知情顺序变化必须在spec显式标注，并接受FULL。

## MAP-CONFLICT：冲突枚举

剧情点主冲突只使用下列枚举；复合事件选主类：

| 类型 | 识别特征 | 动态漫重点 |
|---|---|---|
| 身份碾压 | 隐藏身份/地位反转 | 揭晓与群像反应 |
| 打脸复仇 | 压制→反转 | 触发、反击、结果 |
| 实力碾压 | 战斗/一招制胜 | 连续动作与结果 |
| 情感爆发 | 决裂/表白/生离 | 外化表演 |
| 逆袭翻盘 | 低谷→升级反击 | 代价与新状态 |
| 权谋反转 | 计划/立场翻转 | 信息流和动机 |
| 悬念揭示 | 线索/真相 | 不提前答案 |
| 温情转变 | 护短/重逢/态度转变 | 关系行动 |
| 经营进账 | 生意/物资/数字成果 | 实物与数字可视化 |
| 调查突破 | 线索/证人/物证 | 物证与推理链 |

需要新类型时先更新枚举，不能临场自造下游无法识别的词。

### 强度

| 等级 | 数字 | 用法 |
|---|---:|---|
| S | 9–10 | 全书高潮级，必须保留 |
| A | 7–8 | 重要推进 |
| B | 5–6 | 一般冲突/蓄势 |
| C | 3–4 | 铺垫，可压缩 |
| D | 1–2 | 过渡，可删除 |

集强度取本集最高剧情点，可按钩子组合±1。拆解值是预估，成稿后由台账覆盖。

## MAP-HOOK：情绪钩子

| 标记 | 类型 | 切点属性 |
|---|---|---|
| 💥 | 爽点释放 | 高位收束 |
| 🔨 | 压力蓄积 | 切断等待释放 |
| 💔 | 情感冲击 | 切断或余波收束 |
| ❓ | 悬念牵引 | 问题处切断 |
| 🔥 | 燃点激发 | 高位收束 |
| 🌼 | 温情治愈 | 暖点收束 |
| 😂 | 喜剧笑点 | 笑点完成后收束 |

每个剧情点至少一个主钩子。连续3点不使用相同钩子；💔不宜连续超过2点。付费强冲突模型的💥通常需先有🔨，温情/喜剧模型不强套该规则。

## MAP-FIDELITY：压缩与保真

允许手法：旁白/字幕快进、心理外化、场景跳切、短闪回、功能性角色合并、同一冲突并场。

硬边界：

- 删除冗余过程，不能删除因果触发、行动主体、关键结果和代价。
- 场景跳切必须保留动作、声音、台词目标、道具或时间字幕中的至少一条桥。
- 内心描写按“可演动作→台词→OS→删除”路由，不把心理直接写成画面。
- 保真免费模式下，有独立弧光、关系或伏笔功能的具名角色不得合并；并场不能改变知情顺序、动机或结果。
- 包袱→笑点、出招→结果、提问→揭晓、触发→反应是完整呈现单元，不从中切集。

通常可压缩：重复日常、修炼过程细节、世界观长解释、多轮同义试探、纯赶路。仍须保留最终状态及其获得方式。

## MAP-GENRE：题材路由

- 都市爽文：身份揭露、打脸、权力/财力结果和反击宣言优先；商业过程可压缩。
- 玄幻修仙：境界结果、关键招式、师门关系和反派登场优先；打斗预估分拍和VFX。
- 古言/权谋：动机、信息流、关系转折和机锋归属优先。
- 悬疑：关键线索与物证缺一不可，真相答案不提前到原著揭晓顺序之前。
- 种田/温馨/萌宠：温情、经营进账和喜剧完整单元优先，不强造高压反派。

发行形态：付费项目执行卡点；免费/番剧式在progress显式登记豁免。保真免费模式只对齐原著自然节点，不为百分比移动事件。

## MAP-EPISODE：分集算法

1. 按原著顺序排列剧情点。
2. 从第二个点起寻找切点：压力/悬念/情感问题适合切断，爽点/燃点/温情/笑点完成后适合收束。
3. 通常每集2–4点；完整呈现单元优先于数量范围。
4. 全B/C纯铺垫集并入相邻集；同集两个S级高潮通常拆开。
5. 校验每集入口状态、事件推进、完成态/未了动作、下一集问题。
6. 校验强度曲线：连续两集≤4可能过缓，连续两集10可能透支；题材模型可给出有据例外。

不预设固定总集数。按内容密度滚动估算，九节点是观察位，不是改造原著的理由。

## MAP-SHOOT：可拍性预警

打斗、法术、追逐、群战、天象和大场面追加：

```text
- 可拍性：预计X拍｜同框N人｜换景X次｜关键资产/特效
```

- 关键交手按起手→释放→命中/防御→反应估算3–5拍。
- 具名特写/台词角色超过5人时预警，剧本期用远景和群杂声轨消化。
- 单剧情点跨3个以上物理场景时预警并场或拆集。
- 每个新物理空间和关键道具都要能进入视觉源事实，不把场景别名拆成新资产。

## MAP-TEMPLATE：剧情点模板

```markdown
## 批次 N：第X章 ~ 第Y章

### 【剧情XX】标题
- **原著章节**：第X章 ~ 第Y章
- **原著锚点**：第X章｜邻近关键词/短引
- **原著内容**：按事件顺序概括，不省行动主体、触发和结果
- **行动主体/承受主体**：A｜B
- **信息流**：事件前谁知道什么 → 通过何事 → 事件后谁知道什么
- **冲突类型**：枚举
- **冲突强度**：S/A/B/C/D
- **情绪钩子**：emoji＋类型
- **必保清单**：原文引句/动作｜归属角色｜顺序；无则写无
- **改编处理**：原序保留/压缩/并场/删除｜理由与不变项
- **保真锚点**：仅保真模式命中时填写
- **可拍性**：命中风险时填写
- **归属集数**：EP-XX
- **状态**：待用
```

批次小结至少写：章范围、剧情点范围、分集映射、强度序列、新增角色/别名、伏笔、期限、口径、原著相对时间锚、视觉事实增量、未决问题。

伏笔名是未来收割键，必须稳定；拆解期状态为“待埋设”，摘录占位统一写“（待回填）”。

## MAP-VISUAL：视觉源事实

只登记本批确定会进入改编的有据稳定事实：

- 人物：身份、性别/年龄阶段、原文稳定外观、特殊标志、服装类别、别名、证据。
- 场景：唯一物理空间身份、规范名、精确别名、世界层、固定结构、证据。
- 道具：正式名、别名、形制/材质/颜色、关键文字、初始持有人/状态、证据。

`map-preflight`会强制每个事件填写`visual_deltas`：已登记道具命中颜色、形态、破损、显露或易主变化却未写增量时FAIL；标为`VOC/不可见声音角色`的实体若承担抬头、挥手、抚须、打人等可见动作也直接FAIL。

不写最终文生图提示词。原文无审美细节时用 `原文未明示，交下游美术补足`；具名固定脸实体的性别/年龄不能无据进入READY。

完成正式剧情点后执行`goal-runner Next`给出的preflight与quality命令。主编不预读source-checker；Plan自动生成只含本轮维度的checker brief。
