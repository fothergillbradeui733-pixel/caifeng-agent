# 原著保真优先＋免费番剧式分发模式

本文件是组合模式的唯一权威规则。只有用户按 SKILL.md「启动」第2步明确选择、输入 `~start --mode fidelity-free`，或现有项目 `progress.md` 已登记该模式时启用；不要仅因用户说“少改一点”而静默切换。

## 一、模式定义与落账

本模式固定两个维度，第三个维度仍按题材选择：

- 改编策略：`原著保真优先`
- 发行形态：`免费/番剧式分发`
- 节拍模型：打脸/逆袭/悬念主线选 `强冲突模型`，日常经营/治愈主线选 `高底线温情模型`；本模式不执行付费卡点

在 `progress.md`「基本信息」逐字登记：

```markdown
- 组合模式：原著保真优先＋免费番剧式分发
- 改编策略：原著保真优先
- 发行形态：免费/番剧式分发
- 模式生效范围：全项目
- 模式确认：YYYY-MM-DD·用户选择（命令参数/自然语言回复）
```

在「全局节拍卡」登记：

```markdown
- 付费卡点：豁免（原著保真优先＋免费番剧式分发，~start 确认）
- 九节点落位：原著自然节点对齐（按当前已拆原文登记；百分比仅作观察，不强制移位）
```

旧项目中途切换时不得默认为全项目：先运行 `~status`，再将「模式生效范围」写成 `EP-XX 起`；若用户要求追溯覆盖旧集，对目标区间执行 `~polish N-M` 并使旧 PASS 失效。把切换决定和覆盖范围写入 `audit-log.md`。

## 二、决策优先级

发生取舍冲突时按下列顺序裁决：

1. 原著事实、因果、人物动机、关系转折、知识边界、伏笔与揭晓顺序
2. 名台词、名场面、关键笑点及其归属与前后节拍
3. 单集可看性、视觉化和自然追更钩子
4. 商业强度、固定百分比节点和人为延宕

免费番剧式仍须有追更动力，但不得为了卡黑把一个完整揭晓、反转兑现、笑点包袱、战斗结果或情感对话从中腰斩。优先在原著已有的疑问、行动启动、局势变化或满足感高点收束；无自然悬念时允许以完整小闭环结束，不制造“答案就在下一秒”的付费断点。

## 三、保真边界

### 允许直接执行

- 压缩重复心理、重复解释、赶路、修炼轮次和无信息增量的过渡
- 把原著心理转为角色 OS、台词、动作、反应镜头或声画设计
- 在不改变事实和功能的前提下并场、缩短对话轮次、调整镜头顺序
- 增加原场景中既有在场者的反应拍、景别、音效和视觉特效

### 必须登记

每个剧情点填写 `改编处理`；涉及主线因果、角色弧光/关系转折、伏笔线索、信息揭晓、设定上限、名台词/名场面/关键笑点时另填 `保真锚点`。合法处理枚举为：`原序保留 / 压缩 / 视觉化 / 移位 / 并场 / 删减`。

`移位 / 并场 / 删减` 必须同时写明原著出处、理由、落点或去向，以及“未改变何种因果/信息差/人物关系”。不得用“节奏需要”作为唯一理由。

### 必须交用户决定

下列变化不得由主编自行决定：改变核心事件结果；改变人物关键动机或关系转折；提前/延后身份、真相、凶手或关键伏笔揭晓；删除 S/A 级剧情点；合并有独立弧光或伏笔功能的具名角色；改变结局。获得决定后在对应剧情点 `改编处理` 与 `audit-log.md` 双处登记。

## 四、拆解与分集加严

- 不使用未来高潮闪前作为爆炸开场，除非原著本身采用该结构或用户批准；第 1 集从开篇原著素材中找冲突、反常或人物困境
- 九节点只对齐原著已有自然节点；原著节点偏离百分比时记录偏离，不移动事件、不补造事件
- 原著连续名场面视为一个“完整呈现单元”；不能在触发与反应、包袱与笑点、出招与结果、提问与揭晓之间切集
- `保真锚点` 至少覆盖：事件结果、因果触发、行动主体、知情人/信息来源、关系或状态变化；无适用项写 `无（纯过渡）`
- 批次小结列出所有非 `原序保留` 的处理，形成可导出的保真取舍摘要

## 五、写作加严

- 剧本集头使用：`模式：动态漫｜改编策略：原著保真优先｜发行形态：免费/番剧式分发`
- 强化只能增加表现强度，不能增加剧情功能：不得新造施害、救援、误会、证据、决定、能力、关系或结果
- “先压后弹”只能强化原著已有反派行为或台词，不另造反派恶行；“观众视角”仅使用原著在场或场景逻辑必然存在的群体；“信息不对称”不得让观众提前知道原著此时尚未揭晓的信息；“延时引爆”只能调镜头停顿，不能新造断电、来电或闯入打断
- 强度 ≥9 集优先选用所有有原著前提的强化技术；不足两项时，在集头写 `爽点强化配置：[已用技术及落点]＋保真豁免〔原著无第二项强化前提·剧情点XX〕`，改用景别、音效、动作分拍增强表现。不得为了满足“≥2项”计数补造前提
- 角色合并、事件移位和冲突前置必须服从本文件「三」；与 map-card/write-card 的一般强化规则冲突时，以本模式为准

## 六、专项质检与交付

source-checker 和 script-checker 在基础维度之外输出 `保真免费模式专项`：未启用写 `N/A`，启用时必须 PASS 才能签发。

专项至少核对：模式落账完整；所有保真锚点有下游锚点；非原序处理有据且有去向；无新增剧情功能；无付费式硬切；九节点未反向驱动原著改序；需用户决定的变化已有书面记录。

`~export` 在本模式下附“保真取舍摘要”：按 EP 列出所有 `压缩 / 视觉化 / 移位 / 并场 / 删减` 条目及依据；若全为原序保留，明确写“无实质剧情改动”。
