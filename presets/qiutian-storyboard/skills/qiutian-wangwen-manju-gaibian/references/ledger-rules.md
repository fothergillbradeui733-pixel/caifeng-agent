# 台账与状态管理检查单（ledger-rules）

> 本文件仅服务载体修复、状态规则、批量改写/拆并集和异常对账。日常写作按`write-card.md`的`WR-CLOSE`生成登记块，事务顺序服从pipeline，不读取本文件。

---

## 一、载体布局

项目目录树见 workflow.md「项目布局」（唯一出处）。**布局纪律**：

1. **progress.md 只存当前状态**；审查报告反馈、逐集修复过程、精修记录等**过程性记录一律写 `audit-log.md`**（progress 里最多留一行指针）——过程记录常驻 progress 是文件膨胀到 300KB 的主因之一。
2. **分表兼容**：存量项目「伏笔在 progress 区块内、角色卡在 plot-map 内」的旧布局**继续合法**（lint 双兼容，两处任一即可）；**同一台账严禁双载体并存**（lint 报 WARN）。
3. **分表迁移触发（存量项目，可选）**：progress.md 超过 100KB、或「待回收伏笔」区块超过 80 行时，建议把伏笔台账整体迁入 `ledger-foreshadow.md`（progress 区块只留一行指针 `→ 见 ledger-foreshadow.md`），角色卡同理迁 `character-cards.md`（plot-map 留指针）。迁移登记一行「迁移记录」。
4. **新项目（~start）**：直接按分表布局建档。

## 二、progress.md 区块清单（载体齐备性检查基准，缺一即需迁移回填）

基本信息／拆解进度／创作进度〔各集字数〕／角色状态快照〔就地覆盖〕／快照史／待回收伏笔〔分表布局下本区块为指针行〕／道具信物台账〔含别名列〕／场景名登记表／原著时间锚〔逐集source_time_contract〕／未了期限／开放行动线清单／设定数字口径表／高频意象表／全局节拍卡／上集末场快照〔含快照来源〕／源文件缺口／迁移记录。

完整格式模板 + 填写示例见 `{{SKILL_ROOT}}/references/progress-template.md`（~start 建档时读；日常按定向读法只读相关区块）。

**存量项目迁移规程（载体齐备性检查）**：~start 恢复项目时核对 progress.md 是否含上述全部区块、角色卡是否为七列（在 plot-map 或 character-cards.md 任一处）——**任一载体缺失，必须先迁移回填再继续创作**：①按格式补建空区块；②从已成稿剧本回填关键条目（口径表、台账、末场快照按最新集；意象表跑一次目录级 lint 全量指纹机扫播种；节拍卡从各集头部「情绪强度」提取——可直接用 `-FixProgress` 补账）；③回填结果登记一行「迁移记录」。**严禁在载体缺失状态下继续 ~write（规则会静默降级）**。

**会话级轻量检查**：每会话首次 `~write`/`~map` 启动时跑一条命令替代逐区块目检：

```
powershell -NoProfile -ExecutionPolicy Bypass -File {{SKILL_ROOT}}/scripts/script-lint.ps1 -Path . -Startup
```

＝载体 17 区块齐备 + 七列角色卡 + 避让缓存 + 全套 `-CheckProgress` 新鲜度，一次跑完。**同一会话内上一集台账已收割清零（FAIL=0 且 TODO 清零）的，后续启动可跳过；新会话/恢复会话/批量收尾后必跑**。报「载体缺失」FAIL → 先迁移回填再创作（防换会话直接 ~write 时规则静默降级）。

## 三、常驻关键公式与规则（每集都要用）

- **原著相对时间**：只保存原著明确原话，如当日、次日、七日后、半个月后、出发前四天、秘境开启前三天；不把它们换算为“第X天”，不补算原著未给出的绝对日期
- **三条时间安全门**：原著事件先后不可颠倒；明确相对时长数字不可改；闪回必须明确早于当前事件。晨/日/黄昏/夜只作拍摄时段
- **期限兑现**：保存「原著时间原话＋待按原著兑现/已按原著兑现/已失效＋原著证据」，不计算立约日或到期日
- **逐集跟到最新成稿集**：各集字数／原著时间锚／各集强度序列／上集末场快照「快照来源」四项必须每集更新，lint `-CheckProgress` 差集核对、停更即 FAIL
- **就地覆盖**：角色状态快照、上集末场快照均**每目标唯一条·就地改写**，旧值移「快照史」，严禁多条并存双口径
- 口径表冲突当场归一、不得双口径；伏笔状态枚举 待埋设→待回收→已回收（EP-XX）；意象表登记以 lint 聚合段/缓存为准（≥3集避让）

## 五、状态管理原则

- 剧情点状态：`待用` → `已用`；章节状态：`待处理` → `已拆解` → `已转化`
- 伏笔追踪：`待埋设`（拆解期登记，无剧本可摘录）→ `待回收`（埋设集创作完成，摘录已填）→ `已回收（EP-XX）`；**埋设集创作完成的同时**，必须把埋设场次的剧本原文摘录写入台账对应条目——回收集相隔几十集后，这段摘录加埋设集剧本就是唯一可靠的细节依据。**状态词白名单＝｛待埋设／待回收／已回收（EP-XX）｝**，禁用「开放留白／进行中／已升级」等自创词（确需分层先在本原则白名单化）；lint `-CheckProgress` 校验状态词合规 + 『待埋设』逾期（埋设集 ≤ 最新成稿却仍待埋设＝FAIL，须转待回收并补摘录）
- `~rewrite`/`~polish` 修改某集后，该集涉及的全部台账条目（埋设摘录、道具状态、原著时间锚、期限兑现状态）必须按新版剧本重新核对更新；若该集埋设的伏笔已在后续集回收，须提示用户复核回收集是否仍与新版一致
- 道具/信物：首次出现即入台账；每次易主、移交、损毁立即更新——**已移交/损毁的道具严禁在后续集「复活」**（如已上交的戒指不得再被佩戴）
- 场景名：每集完成后把新地点登记「场景名登记表」；同一地点沿用已登记写法（见`WR-ASSET`，lint以`.lint-cache.json`兜底）
- 原著时间锚：每集只登记原著时间原话、事件先后、闪回边界和结束状态。旧项目已有绝对日历冻结，不批量删除，也不继续读取、更新或校验
- 角色改名/别名（**资产名唯一性**）：角色卡第1列＝资产名，**说话人行与出场人物表只许用资产名**。①改名：登记**生效集**（`旧名→新名（EP-XX起）`），生效集之后旧名失效；②**并存别名**（绰号/婚前名/真名/身份称呼如"石头他爹"）：登记 `某名（仅台词）`，只许出现在台词/△ 内——**不登记的后果是跨集换名被制作端拆成两个角色资产，且两集各自集内自洽、单集质检看不出来**；③项目淘汰名登记 `某名（禁）`，全文出现即 FAIL。三种格式均由 script-lint「资产名唯一性机扫」自动拦截（脚本自动读取 character-cards.md 或 plot-map 角色卡「别名/改名」列）
- **能力上限口径（约束类）**：口径表中带「不得／上限／极限／最多／封顶」字样的能力/战力/财力上限条目，每集出现主角战绩展示时必须逐条比对；超限时剧本须有「吃力／见汗／代价」可拍演出，否则视为设定崩坏（script-checker 维度2 硬核对）
- **开放行动线保温（防暗场线断桥）**：「开放行动线清单」登记〔谁·去做什么·发起集·最后提及集〕；某条行动线连续 2 集未被提及、却在后续集突然引爆重大升级（受伤/谈崩/身亡）＝断桥——中间集须插一个保温拍（一句台词/一条消息/一句 OS）
- 所有状态变更立即写入对应文件
- 已初始化视觉交接范围内，人物/场景/道具稳定事实写 `visual-assets/source-facts.md`，逐集出现与状态写 `visual-assets/episodes/EP-XX.md`；按作用域判定视觉是否失效，变更后先Sync/Preflight，再增量Validate/Index。不要把文生图审美补足写进上游事实文件

## 六、批量改写规程 + 批量操作回归

- 跨集批量改写（格式统一、标签迁移、清扫类）开始前，必须先定义目标格式的**唯一规范形**（如补字幕只许 `【字幕：…】`），禁止改写过程自创变体——修复管线本身就是格式漂移的高发源
- 涉及**归属/语义**的机械改写（如内心OS标签角色化、说话人名变更）**必须对照原著叙述主体**判定归属，禁止仅按"就近说话人"推断——错挂会破坏知识边界与伏笔因果
- **批量操作回归**：任何跨集批量改写后运行目录lint并逐文件生成quality scope Plan。纯换行/装饰格式走MACHINE，时间/台账/视觉走定点，行动主体、说话人归属、正文或接缝变化走FULL；禁止把所有被改文件无条件全维重签

## 七、拆并集规程

- 拆集/并集（PASS 失效规则点名的重构操作）会让**以 EP 编号为键的 7 类载体**全部指针失效，必须按清单逐项重编号：① progress「各集字数／原著时间锚／各集强度序列／快照来源」② 伏笔台账「埋设于 EP-XX／计划 EP-XX 回收」③ 道具台账「首次出现 EP-XX／变动记录 EP-XX」④ 未了期限「登记于 EP-XX」⑤ 高频意象表「已用集数」⑥ 全局节拍卡「付费卡点 EP-XX」⑦ plot-map 剧情点「归属集数」+ scripts 文件重命名与集数头
- 完成后强制全量机扫回归（`script-lint.ps1 -Path scripts` + `-CheckProgress`）+ 受影响集及其相邻集 PASS 全部失效重检

## 八、会话恢复·对账·导出

- **`~status` 对账**：普通查询运行 `project-status.ps1 -ProjectRoot . -Fast`；hash变化自动全检。`~status --full`强制目录lint、progress、视觉全检及quality收据汇总。机械PASS不替代语义收据；数值不符、剧情点待用、缺收据或scripts存在未登记EP时，先运行quality Plan决定FULL/定点/机器复检，禁止无条件重跑checker。UNRESOLVED允许继续后续集，但阻断无说明导出，必须在任务末报告
- **Commit收割预检**：长跑批次在正式`-FixProgress`前必须通过`ledger-commit-preflight.ps1`的临时镜像演练。演练读取同一scripts、根目录Markdown和policy，任何TODO/FAIL或冲突只作用于临时副本；正式项目不得留下“快照已刷新但后续冲突退出”的半事务状态。
- **`~export` 异常门**：含未质检草稿必须显著告警，不得静默混入
- **源文件缺口／迁移记录**：progress.md 尾部两个登记区块——「## 源文件缺口」（章号+症状+补源状态）与「## 迁移记录」（日期+回填内容**一行式**）；~start 预建、缺口/迁移时追加，progress 迁移记录只留一行结论
