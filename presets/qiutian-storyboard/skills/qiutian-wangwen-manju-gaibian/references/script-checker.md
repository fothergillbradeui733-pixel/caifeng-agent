# 剧本语义质检卡 V6

## 角色与边界

作为独立只读 checker，核验单集或连续批次剧本的原著准确、接缝、叙事、台词、可拍性与平台合规。不得修改剧本、台账或视觉文件。权威lint已经证明的格式项不重复检查。

严格执行 `quality-receipt` 给出的 FULL、DIFFERENTIAL 或 TARGETED 维度。

## 输入

- quality Plan生成的checker brief：剧本路径/hash、模式、轮次、指定维度、writer brief与Review增量路径/hash。
- checker按writer brief列明的路径自行读取目标原章、剧情点、接缝事实与风险材料；完整Write JSON仅作歧义审计回退。
- 权威lint输出必须`FAIL=0`；包外预答只接受带章号、剧情点、角色卡或台账行的证据。
- 复检轮另读修改diff、最新hash/lint和上一轮问题四元组。

hash在检中变化或材料缺失时返回 `FAIL_INPUT`，不采信旧结论；主编必须重建Review包并重新派发，`FAIL_INPUT`不属于语义FAIL、不增加failure_count。

## 核心维度

### 1. 原著、因果、主体与知识边界

- 本集覆盖的原著事件、结果、顺序和代价准确。
- 行动主体、承受主体、道具持有人和台词归属准确。
- 角色只使用当时已知信息；揭晓不提前，误会不被擅自消除。
- 编号事件不重复，人物/道具/境界状态不在原著揭晓边界前显形；集头声明的事件必须在正文找到场次证据。
- 压缩、并场和视觉强化不改变核心因果或人物动机。
- 必保台词/名场面/笑点/伏笔按剧情地图落地。

任一失败均为结构性失败；修复后通常需要FULL。

### 2. 跨集与集内连贯

逐项核对：

1. 上一集末场的原著时间锚、地点、在场人物、姿态和未了动作。
2. 上一集末场快照、未了动作和人物/道具状态逐项接续。
3. 本集场景之间有可理解的因果、时间或空间桥。
4. 人物伤势、服装、境界、称呼、道具归属和行动线连续。
5. 原著事件先后不可颠倒，明确相对时长数字不可改，闪回必须早于当前事件；不得补算原著未给出的绝对日期。晨、日、黄昏、夜及箭头跨时只校验当场拍摄时段自洽。
6. 末两场为下一集留下可执行状态，不靠全知旁白硬造钩子。

### 3. 节奏与情绪

- 本集有明确推进，不是原著摘要堆叠。
- 高强度集的强化配置有实际落点；保真模式不为凑技术新增剧情功能。
- 反应拍不重复刷同一情绪；集尾自然收束且不切断完整呈现单元。

### 4. 数据结构专项

仅在FULL或计划指定时检查语义相关结构：集头映射是否与内容一致、人物标签是否导致主体混淆、机器未覆盖的特殊结构是否会误导下游。装饰线、字数、标点和白名单格式以lint为准。

### 5. 台词质量

- 台词符合人物身份、关系、情绪和知识边界。
- 不用解释性对白重复画面，不把作者说明塞给角色。
- 名台词保留其归属、语义和前后触发。
- 近集口癖和句模无明显机械复读。

### 6. 容量

机器字数通过后，只判断是否因过度压缩造成事件、反应或因果缺拍，或因重复说明拖慢成片。

### 7. 可拍性

- `△`只写镜头和声音可呈现的内容；心理、判断和抽象状态必须外化或使用合法OS。
- 场次首拍落地，人物/地点/动作关系清楚。
- 战斗保留起手→释放→命中→反应；武器、法术和防御物不凭空出现或破坏。
- 同框人数、换景、特效与镜头动作具有基本制作可行性。
- 视觉状态变化、关键道具和场景身份能被交接文件准确承接。

### 8. 平台合规

每集必查，不得因差异化质检省略：极端血腥、色情、未成年人不当内容、仇恨歧视、违法行为鼓励及其它明显平台风险。必要时提出不改变剧情功能的可拍替代表达。

### F. 保真免费模式专项

启用时检查：因果、人物弧光、揭晓顺序、设定上限和名场面没有为卡点、爽点或视觉刺激被改造；完整呈现单元没有切断。

## 质检路由

| 计划 | 检查范围 |
|---|---|
| FULL | 1–8及适用F |
| DIFFERENTIAL | 固定1、2、7、8＋risk_flags命中维度 |
| TARGETED | 只查收据指定维度/作用域，但平台合规8仍需快速核对 |
| MACHINE | 不启动语义checker；采信权威lint和scope plan |
| REUSE | hash与全部作用域未变，复用收据 |

风险路由：高强度→3；揭晓/伏笔→1/2；战斗/VFX→7；名称/状态→2/5/7；保真→F。

## 失败与复检

- 第一次FAIL：同一checker只看问题四元组、diff和失败维度。
- 第二次仍FAIL：收据要求新的checker FULL。
- 第三次仍FAIL：输出可持久化问题，主编登记UNRESOLVED并继续；不得继续第四轮。
- 任何复检若发现核心因果、主体、知识边界或接缝受到新影响，设置 `fresh_checker_required=true`。

## 输出

首行：

```text
CHECKER_RESULT {"status":"PASS|FAIL|FAIL_INPUT","round":1,"checked_hash":"...","mode":"FULL|DIFFERENTIAL|TARGETED","checked_dimensions":["1","2","7","8"],"failed_dimensions":[],"touched_scopes":["core_semantic","continuity"],"fresh_checker_required":false}
```

PASS后给各检查维度的结论与关键证据。FAIL问题使用四元组：

```text
[维度]｜[场次/台词/动作位置]｜[原文或项目事实证据]｜[最小可执行修复]
```

若上一集快照或未了动作与本集冲突，另列：前集状态、当前成稿事实、最小接缝修复。

### 批量输出

收到 `comic-adapt-batch-checker-brief/1.0` 时只输出一个 `comic-adapt-batch-checker-result/1.0` JSON：`episodes`逐集包含单集首行的全部判定字段、raw/core hash、问题四元组和`exit_state_changed`；`seams`逐对包含left、right、PASS/FAIL与证据。任何单集hash变化只把该集记`FAIL_INPUT`，不得使其它集自动失败或PASS。平台合规与维度1、2、7、8仍逐集检查。

## 通过条件

指定维度全部PASS；维度1、2、7、8无失败；适用F通过；权威lint `FAIL=0`；文件hash与派发时一致。
