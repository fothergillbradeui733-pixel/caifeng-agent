# 秋天 视觉资产提示词

把长篇剧本整理为可被下游稳定引用的视觉事实源。完整建库/升版时交付同版本资产库与去正文索引；下游缺资产补齐时默认交付独立资产库补充文档；长篇并发收口时生成新的合并补充文档。以确定性脚本完成格式校验，并以机检结果作为交付依据。

## 核心契约

1. 专注生成静态视觉资产文生图提示词；视频分镜、动作中段、机位、运镜和时长交由对应视频提示词技能处理。
2. 角色、场景、道具及其它出图资产统一使用 16:9。
3. 下游管线或视觉风格存在信息缺口时先询问；信息齐全时直接执行一次。
4. 每张卡依次包含 `### @资产名`、`类型：`、本类型规定的元信息、`文生图提示词：`；可见角色与 Q版小人必须显式填写设定性别、外观呈现、呈现性质、颜值定位和特殊标志，角色和不可见声音角色另带音色行。
5. 多状态资产为每个 `@资产名_状态词` 建立可独立出图的完整卡，基础名仅作族名；同一资产各状态的基础锚点段逐字相同，变化范围限定为有剧本证据的状态变量。
6. 场景同时出现白天与夜晚时拆为 `_日` / `_夜`；两条提示词以 `白天` / `夜晚` 作为唯一文本差异。日夜保持独立维度，破败、回忆等状态各自归入对应状态轴。`全局实体索引` 已锁定建议名且未列日夜卡时逐字保留建议名，提示词使用时段中立母版，具体日夜由场次头控制并在说明登记。
7. 角色与不可见声音角色使用唯一四槽音色 schema，跨集、跨状态逐字锁定。
8. 全剧本排查跨集复用的 generic 群体；有就生成群像卡。零群像必须有明确排查结论。
9. 旧库升版时以旧库为事实源，逐字锁定既有卡名和音色；改名、废弃和单状态首拆多状态走受控通道。
10. 完整建库/升版时同步生成 `{剧本名}_视觉资产库_V{N}.md` 与 `{剧本名}_资产索引_V{N}.md`，运行 `validate_assets.py`；修复所有 FAIL，并把 warning 收敛到有证据的例外项后交付。
11. 音色中的性别只服务配音；视觉性别以卡内元信息和文生图正文为准。可见人形角色的设定性别、当前外观呈现与扮装关系同时进入两处；剧情刻意隐去性别时使用 `设定性别：剧情刻意未明示＋外观呈现：中性`，正文写成“剧情保留性别悬念的中性人物，完整、清晰呈现面孔”。普通信息缺口依次查用户指令、剧本、角色台账和原著证据，仍待确认时询问用户。
12. 所有可见人形资产都呈现人脸：角色与 Q版小人使用完整清晰的正脸或三分之二侧脸；群像中的 3–6 人逐一具有完整、清晰、自然差异化的面孔并保持 generic 身份；原著明确蒙面、遮脸或无脸时按证据呈现。脸部采用“审美簇＋1–2 个可执行识别锚点＋原文特殊标志”的最小充分结构；通用美貌词只承担颜值结论。主要角色同时出现四类以上脸部微结构时，保留最具识别作用的部分。
13. 服装提示以设计语言呈现。原文款式留白时，使用“身份/场合＋外显性格＋内在张力＋轮廓/色彩/材质/结构/装饰中的 2–4 项＋固定记忆点”，并采用单一确定方案；最终选定的定妆图负责锁定具体款式。
14. 多集项目逐集运行源覆盖审计。跨集说话人、跨集前景人物和剧本明确要求固定脸/服色的具名人物使用角色卡精确映射；群像专门承载 generic 背景层。每个源标签通过角色卡、群像卡或别名实现唯一映射。
15. 每个重复场次头地点精确命中一个场景资产名或别名。同一物理空间改称、扩写或机构更名时并入别名和出现集；每个物理空间保持一张卡，地点覆盖采用精确匹配并显式登记。
16. 场景固定结构、陈设和视觉符号逐项对应剧本证据或说明中的授权美术补足。自动模板只采用完整词或经审阅的词典匹配；“江”等单字仅作名称组成部分。
17. 日卡词汇限定为白天语义，夜卡词汇限定为夜晚语义；现实层、幻境层、极境层等互斥世界层分别使用独立母版。剧本明确要求同屏叠合时，说明同步登记证据。
18. 源覆盖同时核对名称与映射类型。甲乙丙丁、序数长老、前景锁定人物和跨集独立说话人映射到角色卡；群像对应 generic 背景层。审计输出 `源标签→目标卡→卡类型→对白/场次证据`。
19. 单集人物达到 4 句对白，或至少跨 2 场且有 2 句对白时，采用角色卡，或在 `资产化决策台账` 登记逐镜内联/不资产化及依据。主角或主要人物的幼年、童年、具体年龄变体建立年龄状态卡。
20. 旧版兼容卡完整保留，并以 `使用状态：已废弃` 和 `替代资产：@有效项/多个 @有效项/逐镜内联` 退出活动索引；有效卡写 `使用状态：有效`、`替代资产：无`。群像明确为 3–6 人；有效视觉状态只使用静态可见差异词。
21. 接到 `qiutian-3dman-shipin-tishici` 缺资产调用时，允许下游先在原分组正文直接使用规范化的缺失 `@资产`，再生成一份独立、追加式资产库补充文档；主库、全量资产库和索引保持原样，正式升版由用户明确指令触发。最终交付前，主库/索引与全部补充文档共同通过重复 `--lib` 机检，每个 `@资产` 精确闭合。
22. 合并多个补充文档时保留全部源文档，生成下一空闲 S 序的新合并文档；同卡同文只保留最早来源。同名异类型、同名异文、别名多指、音色/特效异文、状态时间线或闭合映射冲突进入阻塞清单并列出受影响集；加载语义以全局唯一事实为准。
23. 输入是 `comic-adapt-fidelity` 项目或其 `visual-assets/handoff.md` 时，读取 [comic-fidelity-link.md](references/comic-fidelity-link.md)，先取得上游 `ASSET-LIBRARY-READY`，再运行 `prepare_fidelity_library.py`。标准 JSON 的 `candidate_cards` 是唯一资产发现清单，上游资产化决策不可改判；导入 FAIL 时停止并要求修复交接，恢复后仍从标准 JSON 继续。旧 `comic-adapt` schema 继续兼容导入，并始终保持其原有项目命名空间。
24. 非 fidelity 严格联动模式下，`全局实体索引` 的 `建议@资产名/建议@集合` 中每个 `@资产名` 都是强制候选卡名，并按逐集记录回源核验。fidelity 严格联动模式下，每个 `candidate_cards` 项恰好生成一张完整有效卡，`出现集` 精确采用其 `episodes`；不额外创建基础卡，不扫描剧本或原著发现新卡，仅在事实缺失或冲突时定点回读。完整建库以格式校验、建议闭环审计与 `audit_fidelity_library.py` 精确集合审计全部零 FAIL 为交付门槛。

## 工作流

### 1. 盘点输入与模式

先用 `rg --files` 盘点用户指定目录，再按以下优先级建立事实源：

1. 用户本轮明确指令。
2. 旧版视觉资产库与同版索引（更新模式）。
3. 通过 `import_comic_handoff.py` 校验的 comic-adapt `visual-assets/handoff.md` 标准 JSON；fidelity 严格联动时该 JSON 升为唯一发现清单。
4. `plot-map.md` 的角色别名/改名/禁用名，`progress.md` 的道具别名与场景登记；有效交接已覆盖的实体只做冲突抽查。
5. 按 EP 顺序的分集剧本；有效交接已闭合的目标只定点回读证据，仍由源覆盖审计做最终独立验收。
6. 原著小说只用于补足剧本留白且确有依据的身份事实；改编剧本保持当前画面事实的最高脚本优先级。

comic-adapt 交接导入前置：

```text
python <技能根目录>/scripts/import_comic_handoff.py \
  <项目目录>/visual-assets/handoff.md \
  [--episodes N或N-M] \
  --output <项目目录>/.comic-adapt-cache/qiutian-shijue-zichan-tishici/handoff-<范围>.json
```

- 用户直接给 `handoff.md` 时从其父目录的父目录识别项目根；用户给项目目录时使用固定入口 `visual-assets/handoff.md`。
- 导入 PASS：标准 JSON 是本轮发现清单，按 `source_facts` 与 `episodes` 直接建立内部台账。fidelity 严格联动只处理 `candidate_cards` 并关闭二次发现；其它模式为写卡、消歧或审计定点读取其中给出的剧本路径与证据场次，全量扫描范围只覆盖尚待闭合实体。
- `全局实体索引` 中每个建议 `@资产名` 属于强制候选卡名；资产化决策和上游“原文未明示”标记属于中间发现结果。旧库复用、美术补足、完整卡生成、状态并行组合和最终源覆盖审计仍由本技能负责。旧库出现 `外观呈现：刻意模糊` 时，新版迁移为 `外观呈现：中性`；剧情隐去性别的角色同时登记 `设定性别：剧情刻意未明示` 与证据。
- `原文未明示，交下游美术补足` 视为对审美变量的明确授权：可补脸部审美簇与识别锚、发型细节、既定服装类别内的设计语言，以及纯审美场景陈设；具名/固定脸角色的设定性别、年龄、种族、文字、品牌、关键道具功能和剧情线索继续定点回源或询问用户。generic 群像若该字段明确授权美术补足，可由本技能设定男女混合或单一性别构成并标明为美术设计。
- 导入 FAIL：fidelity schema 立即停止并要求上游修复，修复后继续使用上游资产清单；旧 comic-adapt 或独立扫描模式才按本节的 `plot-map/progress/分集剧本` 发现流程回退，并在交付报告记录 `comic-adapt交接：INVALID＋原因`。
- 入口缺失：在交付报告记录 `comic-adapt交接：NOT_INITIALIZED＋原因`，并使用本节的 `plot-map/progress/分集剧本` 发现流程。
- `--output` JSON 是可删除重建的缓存。生成/建库任务可写项目 `.comic-adapt-cache`；纯只读审计把它写到会话临时目录，或在任务结束时清理。项目事实修改只记录权威文件变化。

识别模式：

- 用户在全季完成后显式调用且输入为 fidelity READY 交接：进入“fidelity 全季正式建库模式”，严格执行 `comic-fidelity-link.md`，一次生成计划指定的正式 V1 库与索引；不走补充文档或分批增量建库。
- 独立完整建库且无旧库：新建 V1。
- 用户要求正式全量升版且有旧库：输出 V{N+1} 并保留旧版；机检带 `--prev`。
- 下游缺资产补齐：默认进入“补充文档模式”。把下游已使用的缺失 `@资产` 视为待审计候选，同时扫描当前剧本的关联状态、音色、特效和必要依赖；新建 `{剧本名}_资产库补充_{范围}_S{N}.md`，主库/索引保持原样。用户明确要求正式并库，或需求涉及改名、废弃、修改既有卡等追加层范围外操作时，走 V{N+1} 全量升版。
- 长篇并发最终收口：进入“多个补充文档合并模式”。读取主库/索引和全部源 S 文档，保留源文档，生成下一空闲 S 序的合并补充文档；最终下游只加载主库/索引＋合并文档。
- 主库尚待创建且当前只有局部缺口清单时，可让补充文档作为唯一 `--lib` 层；用户明确要求建立完整视觉事实源时新建 V1。
- 长篇大体量项目按 10–15 集一批执行增量建库，最后做全量收口；fidelity 全季正式建库模式除外。

下游缺资产调用的输入契约：

```text
调用来源：qiutian-3dman-shipin-tishici
当前剧本：{路径}
原分组视频提示词：{路径；可已含缺失 @资产}
项目目录：{路径}
主资产库：{路径/无}
主资产索引：{路径/无}
既有补充文档：{按 S 序排列的路径列表/无}
缺口清单：{@建议名｜建议类型｜原分组/行号｜剧本证据｜预计复用/近景一致性需求}
既有视觉风格：{风格值/无}
参考风格基调：{主库值/用户指定值/无}
下游管线：qiutian-3dman-shipin-tishici 16:9 3D漫
补充范围：{EP-XX / EP-XX-YY / 批次标识}
输出目录：{路径}
```

补充文档模式完整读取主资产库/索引、全部既有补充文档、相关剧本证据和原分组正文，并以证据完成缺口解析。输入有主库时直接沿用其视觉风格。主库尚待创建且下游管线已明确为 3D漫时，使用本技能默认 3DCG 国漫风格；用户明确指定其它风格时采用用户设置。

补充文档和多文档合并的完整输入/输出 schema、命名、冲突规则、验证命令与回传字段见 [pipeline-contract.md](references/pipeline-contract.md)。先冻结缺口清单和唯一输出路径；有空闲代理时，可把补充文档生成与单文档机检交给一个代理，主实例继续原分组工作。一个代理独占写入该补充文档并回传路径、闭合映射和机检摘要；每个输出文件保持单写者。当前实例在缺少空闲代理时执行。多个源补充文档的最终合并由一个实例整体完成。

### 2. 风格闸门

用户信息存在缺口时，集中询问两个阻塞项：

```text
建议使用 GPT Image 2 生成本资产库中的图片。
1. 下游管线：A. 16:9 横屏 3D漫；B. 真人短剧；C. 其它
2. 视觉风格与参考基调：如 3DCG 国漫渲染／真人写实电影感，以及色调或作品基调
```

用户已选 A 且说“按默认”时使用：`3DCG 国漫渲染（下游：qiutian-3dman-shipin-tishici 16:9 3D漫）`。用户已选 B 且说“按默认”时使用：`真人写实电影感（下游：真人短剧管线）`。资产库头的 `视觉风格：` 必须带下游括注。

### 3. 建内部台账

内部建立以下表，默认作为内部工作台账：

```markdown
| 类型 | 原文名称 | 规范资产名 | 证据集/场 | 必须资产化 | 状态维度 | 建议状态 | 别名 |
```

另建角色视觉身份表：

```markdown
| 角色 | 设定性别 | 性别证据 | 外观呈现 | 呈现性质 | 颜值定位 | 脸部审美簇 | 脸部识别锚点 | 特殊标志 | 服装设计方向 | 生效集/切换锚 |
```

交接含 `全局实体索引` 时另建建议状态闭环台账：

```markdown
| 实体ID | 规范名 | 建议@资产名 | 逐集实际出现集 | 当前剧本证据 | 原著补证 | 美术补足范围 | 完整卡 | 时间线 | 可引用清单 | 文件名表 |
```

逐集完成：

- 有效 comic-adapt 交接存在时，先从导入 JSON 装载实体 ID、类型、规范名、别名、候选 @、逐集出现、资产化决策、状态维度、生效区间、切换锚与证据。fidelity 严格联动直接冻结 `candidate_cards`，跳过全量重扫和源覆盖发现。
- 非 fidelity 严格联动模式下，独立解析 `全局实体索引` 中每个建议 `@`，同一单元格的多个状态逐项入账并按需回源。fidelity 严格联动不重新解析候选集合，只用 handoff 与计划做一致性审计。
- fidelity 严格联动直接采用每个 `candidate_cards[].episodes`；其它模式可扫描 `visual-assets/episodes/EP-*.md` 汇总精确建议 `@`。连续集压缩为区间，离散集保留为多个区间或单集组合，例如 `EP-01、EP-65`。
- 角色归并与禁用名核对。
- 逐集提取场次头、出场人物、独立说话人和“前景固定/锁脸/锁服色”指令；同一标签跨集出现、跨集对白或被明确锁定时，必须落到角色/生物/不可见声音角色/群像卡或别名。
- 具名人物与 generic 群像分层：具名人物承担独立对白、清晰前景或连续表演时建角色卡；群像专门承担 generic 背景，每个人脸完整清晰可见、自然差异化并保持 generic 身份。原著明确蒙面、遮脸或无脸时逐项沿用证据。
- 对每个源人物标签记录目标卡和卡类型；甲乙丙丁、序数身份、跨集独立对白或前景锁定只落到群像时，立即改建角色卡。
- 统计单集人物的对白句数和跨场次数；达到语义门槛且采用逐镜内联/不资产化时，写入机器可读 `资产化决策台账` 并附可复核依据。
- 识别 `幼年江阳/江阳（童年）/六岁江阳` 等年龄标签；基础角色已有卡但缺年龄状态时视为漏状态。
- 可见角色逐一核对设定性别、当前外观身份与扮装性质；女扮男装、男扮女装、日常异性化穿着和舞台扮装分别登记对应性质。
- 对主要角色分配有证据或经用户授权的颜值定位与差异化脸部审美簇；每人补 1–2 个识别锚点。原文标志与“美术补足”分栏记录，朱砂痣、花钿、疤痕、胎记、异瞳等明确标志保持最高视觉优先级。
- 为每个可见角色提炼服装设计方向：先写身份和场合，再把外显性格与内在张力翻译为轮廓、色彩、材质、结构和装饰密度。职业只决定语境，性格决定设计语言，人物矛盾决定结构变化，记忆点决定唯一性。
- 主要空间、重复空间及所有场次头原名核对；建立“原场次头 → 物理空间身份 → @场景卡/别名”唯一映射。机构更名、前后缀扩写和局部称呼先判断是否同一物理空间，再决定并别名或拆卡。
- 剧情关键、需近景一致或跨集复用的道具核对。
- 常驻画外声和有对白生物核对。
- generic 群体全剧排查台账：候选群体 → 出现集 → 建卡/不建卡及理由。
- 所有多状态的视觉证据、维度、生效区间和集内切换锚核对。
- 下游缺资产补齐时，为每个缺口记录最终解析：`缺口→本补充新建/主库复用/既有补充复用/别名归一/逐镜内联/不资产化→目标@资产或最小描述→原分组定位与剧本依据`；剧本证据与本技能资产化门槛优先于建议类型。规范建议名合法且冲突清零时尽量保留，使原分组直接复用；发生复用、冲突改名或非资产化决策时，回传需要替换的精确 `@旧→@新/无 @ 最小描述`。

资产卡聚焦跨镜头复用的静态视觉事实；一次性路人、普通背景装饰、短暂表情、动作、镜头变化和视频过程变化保持逐镜内联。

### 4. 生成完整资产库或补充文档

完整模式严格使用 `references/output-template.md` 的章节顺序；补充文档模式严格使用 `references/pipeline-contract.md` 的补充文档壳层。两种模式的每张卡都遵循 `references/output-template.md` 的对应类型卡结构、`references/asset-spec.md` 的七类卡规则、命名、状态和音色约束，以及 `references/gpt-image-style.md` 的正向表述与风格尾缀。

fidelity 全季正式建库模式另须逐字写入 `output-template.md` 的 `## 来源契约`，并严格采用建库计划给出的版本、路径和候选卡集合。计划返回 `REUSE` 时不改库；返回 `REBUILD_INDEX` 时只重建索引；返回 `BLOCKED` 时停止，除非用户明确要求升版。

补充文档是追加层，只新增完整卡、卡内逐字音色和必要的库级登记；主库/旧补充中的既有卡保持原文。先按主库→既有补充的顺序查重：同一实体命中有效卡或别名时复用规范 `@资产`；同名不同实体/类型、别名多指、既有定义存在差异时停止该候选并回传冲突，加载语义以全局唯一事实为准。已有角色的新状态从完整主卡继承同脸锚点和音色；当前只有索引时，先取得完整主卡再创建状态卡。

多个补充文档合并时，严格执行 `references/pipeline-contract.md` C2.5 中的合并接口（规则自 C2.3 引入）。先建立全局事实键台账，再按主库/索引→源 S 序处理：统一换行并去除行尾空格后，同卡同文只保留最早来源；任一事实异文都进入冲突清单，冲突解决作为合并前置条件。闭合映射、可引用清单、音色、特效、状态时间线和文件名对照从保留事实重新生成。

对多状态角色先写一段“基础锚点”，复制到同角色全部状态卡，再分别写状态段；全部状态直接从同一基础锚点派生。日夜场景同理：先写时段中立的母版，再替换一个时间词。

全局索引同一实体给出多个建议名时，以建议名集合直接定义状态族：每个名称各有完整卡；族内基础锚点逐字一致，状态段只承载该名称经回源确认的静态可见差异；同一角色的音色逐字一致。建议名逐项写入状态时间线、可引用清单和图片文件名对照表。

状态族的每张卡使用自身逐集实际出现集。逐集状态记录缺项时继续回查当前剧本定位集号；仍无法定位时把该状态列入待确认项。实体级 `出现集` 保持发现线索性质，不进入状态卡或状态时间线的生效集字段。

场景提示词逐项从证据台账写入，地点名只承担身份定位。固定视觉符号回指场次动作/说明，或在卡内说明写 `美术补足：场景结构/固定视觉符号`。自动分类脚本只采用完整词或经审阅的词典匹配；`/江/`、`/宫/` 等单字正则仅作候选提示。

角色基础锚点先写设定性别、年龄、颜值定位、脸部审美簇、1–2 个同脸识别锚点和特殊标志，再写身份气质、基础发型、身形与稳定记忆点；外观呈现、扮装和场合服装写入状态段。重要角色的头部正面特写约占画面 40%，正面平视、自然舒展的人像透视，面部作为第一视觉重点。原文脸部识别锚点留白且用户允许美术补足时，按项目审美分层补足并在卡内 `说明` 标明；授权状态待确认时先向用户确认。

服装段使用明确前缀 `服装设计方向：`。先写角色性格与身份产生的设计命题，再选择 2–4 个视觉维度落地；同一张角色卡的头部特写和三视图必须为同一套完整造型，饰品只佩戴在角色身上。提示词只给设计方向，出图选定后以定妆图锁定具体款式。

使用 Codex 的文件编辑能力写盘；本地 Markdown 创建或修改优先使用 `apply_patch`，大文件采用结构化整文件写入工具。输出到用户指定目录；用户未指定且是项目化任务时放在当前项目的交付目录，并遵循当前会话的 workspace/output 规则。

## 边界与质量判断

- 角色卡画面聚焦人物本体、服装和随身饰品；房间、车辆、职业道具、天气和镜头元素分别归入对应资产或下游分镜。
- 场景卡是无人空镜，只呈现空间结构、固定陈设和环境质感。
- 角色/场景覆盖以精确资产名或别名闭合，并通过登记确认实体同一性；同一源标签唯一指向一张场景卡。
- 具名角色承担固定前景脸、独立对白或跨集连续表演时建立角色卡；群像卡专门承载 generic 背景层。
- 场景陈设逐项来自证据台账；“江阳”“江府”“江南”中的“江”只作为名称组成部分，水面、石岸和水纹需要独立证据。
- 白天卡使用白昼语义元素，夜晚卡使用夜间语义元素；世界观存在常驻异常天象时在说明给出剧本证据。
- 道具卡采用白底或中性背景并呈现单一道具；人物使用动作归入下游镜头。
- 不可见声音角色采用剧本明确的可见声音标记占位并配置音色，视觉信息范围与原文一致。
- 参考风格基调专用于场景提示词；角色、群像、生物和道具各自沿用本类型风格尾缀。
- 可见角色必须把设定性别、外观呈现、呈现性质、颜值定位和非空特殊标志写入提示词；群像必须写男性、女性、男女混合或中性人形构成。
- 女扮男装写“女性角色＋男性外观身份＋身份伪装”，男性女装写“男性角色＋女性化外观呈现＋对应呈现性质”；只写其中一层视为身份漂移。
