# 中文竖屏短剧全流程

把短剧创作当作一条有权威源、有阶段门、有机器校验的生产线。追求“爆款导向”，不得承诺播放量、投流回报或必然爆款。

## 先加载所需参考

- 收到参考剧本、压缩包、小说或竞品时，完整阅读 [benchmark-and-discovery.md](references/benchmark-and-discovery.md)。
- 进入立项访谈、补全剧情设定或判断是否已经“讨论透”时，完整阅读 [socratic-development.md](references/socratic-development.md)。
- 设计原创故事、金手指、人物弧或全季大纲前，完整阅读 [story-engine.md](references/story-engine.md)。
- 初始化项目、写正式剧本或维护连续性时，完整阅读 [project-contract.md](references/project-contract.md)。
- 进入终审、视觉资产或交付阶段时，完整阅读 [production-and-qa.md](references/production-and-qa.md)。

只加载当前阶段需要的参考；跨入下一阶段时再读取对应文件。

## 判定任务模式

先识别用户需要哪一层，避免擅自扩张范围：

1. **样本拆解**：只分析已有材料，不改写。
2. **立项共创**：完成访谈、原创命题、人物和规则，不提前写全集。
3. **全季大纲**：锁定项目圣经和逐集推进表，不扩写完整对白。
4. **正式剧本**：建立制作项目并逐集写到用户指定集数。
5. **全流程交付**：在正式剧本基础上补齐终审、视觉资产和正式包。
6. **续写/修订**：先恢复现有权威源、进度、上集快照和未了动作，再只改授权范围。

用户要求“完整剧本”“继续做到结束”或“正式制作包”时，不得停在提案或大纲。用户只要诊断或分析时，不得擅自重写。

## 建立项目

未给定目录时，遵循工作区 `AGENTS.md`；没有额外约定时在当前工作区创建项目，最终包放用户指定输出目录。运行：

```powershell
python "<skill-dir>\scripts\init_project.py" --path "<project-dir>" --title "<剧名>" --episodes 60 --mode "竖屏真人短剧" --duration-seconds 120
```

初始化脚本只允许写入不存在或为空的目标目录。随后立即填写 `PROJECT-BRIEF.md`，不要把占位符带入正式创作。

## 执行八阶段流程

### 1. 盘点与证据化拆解

- 列出输入文件、可读范围、缺失集数、版本、格式和是否存在播放/投流数据。
- 输入含ZIP、TXT、Markdown或DOCX时，可先运行 `python "<skill-dir>\scripts\inspect_sources.py" <输入路径...> --output "<project-dir>\source-inventory"`；读取生成的清单和抽取文本后再分析。
- 将结论分成“文本事实 / 有限推断 / 原创转译”。没有数据时只说具备潜力，不把样本称为已验证爆款。
- 提取可迁移机制，不复制专名、台词、金额组合、核心道具、关键事件顺序和标志性场面。
- 输出 `BENCHMARK-ANALYSIS.md`；若无参考材料，写明“原创直立项”。

### 2. 苏格拉底式立项

- 访谈开始前完整读取 [socratic-development.md](references/socratic-development.md)，并在 `PROJECT-BRIEF.md` 建立访谈状态、决策来源、矛盾和压力测试记录。
- 一次只问一个可决定剧情走向的高信息量问题；不得发送问题清单。每轮从尚未锁定的变量中选择“下游影响最大、当前不确定性最高、其他设定依赖最多”的一个。
- 每次收到回答后，先在内部完成：准确复述意图、标记“用户确认/主创判断”、推导下游影响、检查与旧决定是否冲突、更新未决项；只在复述有助于校准或发现矛盾时向用户展示，再问下一题。
- 用户没有想法、回答宽泛或说“都可以”时，给2至4个差异明确且能改变后续剧情的方向，推荐一个并说明代价；不要用换皮选项制造虚假选择。
- 沿“观看承诺 → 主角与剥夺 → 欲望与内在误区 → 故事引擎及边界 → 核心关系 → 反派资源升级 → 身份/事业阶梯 → 中段失败 → 终局回收 → 视觉气质与禁区”的依赖顺序追问；新答案暴露前置缺口时允许回到上层，但不得重复已经明确回答的问题。
- 至少完成反事实、最坏误用、理性反派、关系能动性、全季承载力和原创隔离测试。设定只能写成类型标签、不能形成可表演的动作与因果时，继续追问。
- 用户说“你来定”“后面不要再问”后，立即进入自主决策模式；主创自行回答剩余问题并记录理由，但仍须完成同一套矛盾检查、压力测试和立项门，不得借机跳步。
- 进入全季大纲前，先输出一次简洁的“立项共识回放”。仍处于互动模式时，只问一个最终纠偏问题；用户已授权自主决定时直接锁定。
- 运行 `python "<skill-dir>\scripts\validate_brief.py" --project "<project-dir>"`。只有必备设定全部为“已锁定”、阻塞未决项为零、矛盾为零、压力测试全部通过且脚本返回 `BRIEF-PASS`，才可进入阶段3。

### 3. 锁定项目圣经与全季地图

按顺序完成：

1. `STORY-BIBLE.md`：一句话故事、受众承诺、主题、时空、人物、规则、事业/身份阶梯、终局。
2. `character-cards.md`：目标、误区、弧光、声纹、关系底线、状态切换。
3. `plot-map.md`：阶段目标链、每集压力、主动行动、当集兑现、物质变化、尾钩。
4. `ledger-foreshadow.md`：伏笔、信息权限、期限、道具易主和回收集。
5. `WRITING-SPEC.md`：格式、字数、场数、年代/行业禁区、规范场景名和资产名。

完成后做一次“60集压力测试”：删掉任意一集若不影响前后因果，则该集需要重构；连续三集若靠同一种辱骂、误会或打脸推进，则更换冲突机制。

### 4. 写正式分集稿

- 一集一文件，命名 `scripts/EP-XX.md`；以5至10集为一批推进。
- 每批开始只加载全局锁定文件、上一批出口、当前批大纲和上集快照。
- 每集必须包含：0至2秒硬钩、6秒内具体利益、主角主动行动、可见验证、一个小兑现、已经启动的下一步尾钩。
- 正文以唯一一个 `【卡黑】` 结束；其后填写台账登记块和快照。
- 每写完一集先运行单集检查；每批写完再检查跨集衔接。发现逻辑冲突时先改权威源，再同步受影响集，禁止只在下游补洞。

不得靠金手指代替知识、专业判断、医疗、法律、经营和责任。反派施压必须服务具体利益；和解必须经过代价、行动和时间。

### 5. 机器校验与语义终审

运行：

```powershell
python "<skill-dir>\scripts\validate_project.py" --project "<project-dir>" --report "<project-dir>\qa\validation-report.md"
```

修复全部 `FAIL`。`WARN` 必须逐条判断并在审查报告中说明保留理由，不能把“脚本通过”当作语义通过。

当环境提供 `qiutian-manju-juben-shenchaguan` 时，在全季结构锁定后使用它做独立审查；主流程仍负责核对审查器误报与遗漏。

### 6. 建立视觉事实交接

- 从最终剧本提取具名角色、状态、场景、近景/复用道具、群像与不可见声音角色。
- 先写 `visual-assets/source-facts.md`，再逐集写 `visual-assets/episodes/EP-XX.md`，最后汇总 `visual-assets/handoff.md`。
- 使用稳定实体ID：角色 `CHR-`、场景 `SCN-`、道具 `PRP-`、群像 `GRP-`、不可见声音 `VOC-`；状态资产用唯一 `@资产名`。
- 修改剧本后必须重算该集SHA256并刷新交接，禁止保留过期 `READY`。

当环境提供 `qiutian-shijue-zichan-tishici` 时，用它生成完整资产卡和提示词；若不可用，按 [production-and-qa.md](references/production-and-qa.md) 的资产卡契约自行完成，不得静默省略。

### 7. 资产闭合与AI制作准备

- 让剧本头部资产引用、正文 `@资产`、逐集交接、全局索引和完整资产卡形成闭合集合。
- 为角色状态建立同脸锚点和切换时间线；同一物理场景不得随意换名。
- 高频具名角色、固定空间、核心证据道具建卡；无固定脸的一次性群像可逐镜内联，但必须登记处理口径。
- 对票据和复杂文字采用后期贴图策略；对多人、机械因果和复杂手部动作在分镜阶段拆镜。

### 8. 打包交付

所有硬门通过后运行：

```powershell
python "<skill-dir>\scripts\build_delivery.py" --project "<project-dir>" --output-root "<output-root>" --require-assets --zip
```

脚本使用新目录交付，不覆盖已有包；生成阅读文件、制作源文件、质检材料、资产包和 `SHA256文件清单.md`。完成后独立复算文件数与哈希，再向用户报告实际结果和未覆盖项。

## 硬门

只有同时满足下列条件才可称为“正式制作版”：

- `PROJECT-BRIEF.md` 已通过立项校验，用户决定、主创假设和禁区来源清楚，无阻塞未决项。
- 集数连续且无缺集、重集；大纲标题与剧本标题逐集一致。
- 每集有主动行动、小兑现、唯一核心看点和非重复尾钩。
- 时间、地点、金额、道具、人物状态、知识权限和规则不互相打架。
- 伏笔、期限、阶段反派和人物弧在终局前有可见回收。
- 全部机器检查无 `FAIL`，语义终审无未处理的致命/重要问题。
- 全季视觉交接均为 `READY`，资产引用零悬空，状态切换有证据。
- 交付清单中的每个文件存在，字节数和SHA256重新计算一致。

## 保持创作完整性

- 先写可验证行动，再写角色宣言；先兑现本集承诺，再抬高下一集问题。
- 每次获利都转化为下一阶段能力，如信用、证据、渠道、团队、资格或制度。
- 让主角为错误承担修复成本；避免“好人永远正确”和无代价开挂。
- 允许家人悔改，但不以哭跪、失忆或一句道歉抹除伤害。
- 不因AI制作而默认压低场面规模；仅在用户明确要求时考虑真人拍摄成本。
- 不输出与样本高度同构的改名稿；原创相似度有疑问时回到机制层重新设计。
