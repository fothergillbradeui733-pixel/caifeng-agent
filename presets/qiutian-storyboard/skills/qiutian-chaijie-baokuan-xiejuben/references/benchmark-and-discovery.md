## 1. 输入盘点

先建立事实边界，再谈“为什么能爆”。

1. 列出每个输入的绝对路径、文件类型、文件数、集数范围、版本和大小。
2. 对ZIP先查看成员清单，确认是否有嵌套压缩包、乱码文件名、重复稿和隐藏版本，再读取正文。
3. 对DOCX、PDF、视频分别使用适配的结构化解析或当前可用技能；不得把二进制文件当纯文本硬读。
4. 标记缺集、残稿、只有开篇、缺少结局、没有播放数据等限制。
5. 同一作品多版本时建立版本优先级，不把不同稿的情节混成一个事实。

建议记录表：

| 样本 | 可读范围 | 文本规格 | 数据证据 | 可支持的结论 |
|:--|:--|:--|:--|:--|
| 作品A | EP01-05 | 每集约2分钟 | 无 | 仅能判断开篇文本机制 |

## 2. 爆款机制拆解

把每个样本分为三层：

- **文本事实**：剧本直接写明的情节、结构、金额、动作和钩子。
- **有限推断**：这些设计可能怎样影响点击、完播、追更和情绪兑现。
- **原创转译**：只保留抽象机制，转换到新题材的做法。

没有真实播放、完播、投流、付费或用户画像数据时，不得写“已经验证”“必然爆”。使用“具备留存潜力”“文本层可能有效”。

逐样本填写机制矩阵：

| 维度 | 要找的证据 | 判断问题 |
|:--|:--|:--|
| 首屏异常 | 0至6秒可见事实 | 不看背景能否立刻知道事情不正常？ |
| 身份剥夺 | 失去婚约、资产、岗位、亲情或名誉 | 观众替谁不平，账能否算清？ |
| 核心欲望 | 生存、尊严、归属、财富、复仇、建设 | 欲望是否一眼能懂且可持续60集？ |
| 信息差 | 观众/主角知道而他人不知道的事实 | 羞辱是否因未来反证而增值？ |
| 故事引擎 | 金手指、专业、重生、身份、资产 | 它能否反复产生新问题而非只给答案？ |
| 规则与代价 | 禁区、错误、消耗、验证 | 主角会不会无门槛躺赢？ |
| 可见验证 | 钱、票据、机器、证人、检测、合同 | 胜负是否能被镜头证明？ |
| 微兑现 | 当集得到的具体结果 | 本集是否还了一笔情绪债？ |
| 尾钩 | 已启动的新动作或突变 | 下一集是否被迫立刻行动？ |
| 升级链 | 家庭→生意→行业→规则等 | 对手和解决方式是否持续换挡？ |
| 关系功能 | 盟友、伴侣、家人、反派 | 角色是否都在推动选择和代价？ |
| 价值落点 | 钱最终转化为什么 | 是否从炫富升级为能力、边界或制度？ |

完成单篇后做横向归纳：只把至少两个样本都出现、或单篇有强因果证据的规律列为“共性机制”；其余保留为个案。

## 3. 原创隔离

原创不是换名字。建立“机制保留 / 表达替换”表：

| 可保留的抽象机制 | 必须替换的表达层 |
|:--|:--|
| 错误估值反转 | 年代、资产、人物关系、触发事件、证明路径 |
| 观众先知 | 预知来源、信息范围、失准方式、公开时机 |
| 家族吸血 | 责任历史、分割物、边界动作、赎错成本 |
| 垃圾资产翻身 | 资产形态、专业能力、产业链和合法路径 |

至少更换以下七项中的五项：时代地域、主角身份、核心关系、故事引擎、核心资产、阶段对手、终局证明。不得复用标志性台词、金额组合、道具组合、场面调度和关键事件顺序。

若一句话梗概仍能与样本逐词对应，退回重做。新项目必须有独立主题，不只是“同样打脸换行业”。

## 4. 两种苏格拉底模式

### 用户访谈模式

用户要求“先问我”“一次一个问题”时启用。每轮只问最能改变下一步设计的一个问题；根据答案动态选择下一问，不照着清单机械念完。

### 编剧自问自答模式

用户要求“用苏格拉底方法脑暴”或已授权自主决策时启用。对每个关键选择写：

1. 现在真正要解决的问题是什么？
2. 最直觉的答案是什么？
3. 这个答案为什么可能无效、俗套或不可持续？
4. 有什么相反方案？
5. 哪个方案最能产生连续行动、代价和镜头验证？
6. 采用什么，舍弃什么，依据是什么？

自问自答必须收敛为决定，不能只堆可能性。

## 5. 单问访谈顺序

按信息增益选择下一问，通常依次覆盖：

1. 观众最想继续看的欲望：翻身、打脸、复仇、爱情、家庭修复或事业建设。
2. 主角在开篇被夺走什么，以及为什么长期被低估。
3. 最具象的“垃圾资产”或被错误估值的东西。
4. 故事引擎能做什么，怎样触发。
5. 代价、禁区、失败模式和是否会升级。
6. 年代、地域、职业和物质稀缺条件。
7. 主角性别、年龄、能力、误区和终局成长。
8. 核心伴侣/搭档是否留下，怎样拥有独立能力与利益。
9. 家庭伤害的责任分配，谁可悔改，需付什么代价。
10. 阶段反派分别掌握何种资源，如何逐层升级。
11. 集数、时长、真人/漫剧、横竖屏、是否考虑拍摄成本。
12. 视觉质感、情绪尺度、合规禁区和必须保留的桥段。

用户回答“你觉得哪个好”时，提供少量差异明确的方案：先给推荐方案，再给理由和它带来的后续剧情，不把选择原样踢回用户。

## 6. 停问条件与决策记录

以下十一项形成闭合即可停问：

- 格式与受众
- 核心欲望
- 主角与开篇剥夺
- 故事引擎
- 规则、代价和禁区
- 核心资产/事业阶梯
- 核心关系
- 阶段反派
- 中段最大失败
- 终局回收
- 视觉与制作约束

把每轮结论追加到 `PROJECT-BRIEF.md`：

| 决策ID | 问题 | 用户答案/自主判断 | 采用方案 | 影响文件 |
|:--|:--|:--|:--|:--|

用户授权自主判断后，将未决项转为“自主判断”，写出一行理由，继续工作。只有可能彻底改变题材、受众或交付范围的事项才重新询问。

## 7. 阶段交付格式

`BENCHMARK-ANALYSIS.md` 至少包含：

1. 样本范围与证据限制
2. 每部作品的开篇结构和情绪曲线
3. 共性爆款机制
4. 各自独有机制与风险
5. 可迁移机制
6. 原创隔离清单
7. 对新项目的明确设计启示

结尾必须从分析过渡到行动：列出新项目要采用的3至7条机制和明确不采用的表达层元素。
