## 1. 标准目录

```text
project/
├── project.json
├── PROJECT-BRIEF.md
├── BENCHMARK-ANALYSIS.md
├── STORY-BIBLE.md
├── WRITING-SPEC.md
├── plot-map.md
├── character-cards.md
├── ledger-foreshadow.md
├── progress.md
├── scripts/
│   ├── _EPISODE-TEMPLATE.md
│   └── EP-01.md ... EP-NN.md
├── visual-assets/
│   ├── source-facts.md
│   ├── handoff.md
│   └── episodes/EP-01.md ... EP-NN.md
├── asset-package/
└── qa/
```

初始化后不要把 `_EPISODE-TEMPLATE.md` 计入正式集数。所有正式稿保持一集一文件；合订本只在交付阶段自动生成。

## 2. 权威源优先级

发生冲突时按下列顺序处理：

1. `PROJECT-BRIEF.md`：用户明确决定、禁区和交付范围。
2. `STORY-BIBLE.md`：主题、世界、人物、故事引擎规则和终局。
3. `plot-map.md`：阶段目标、逐集事件和尾钩。
4. `WRITING-SPEC.md`：格式、声纹、规范名、字数和制作规则。
5. `character-cards.md` 与 `ledger-foreshadow.md`：人物状态、知识权限、伏笔、道具和期限。
6. `scripts/EP-XX.md`：实际表演与镜头事实。
7. `visual-assets/`：从最终剧本派生的制作事实，不得反向篡改剧情。

若上游改变，列出受影响的下游文件并全部同步。不得在两个文件保留互相冲突的“都算权威”版本。

## 3. 项目配置

`project.json` 使用UTF-8并至少包含：

```json
{
  "schema_version": "cn-shortdrama-project/1.0",
  "title": "剧名",
  "episodes": 60,
  "mode": "竖屏真人短剧",
  "duration_seconds": 120,
  "scene_min": 2,
  "scene_max": 4,
  "content_chars_min": 800,
  "content_chars_max": 1200,
  "require_ledger": true,
  "require_visual_ready": false,
  "require_body_assets_in_header": false
}
```

项目锁定后如需改集数、模式或时长，先改配置和 `PROJECT-BRIEF.md`，再重排全季地图；不要只改校验阈值掩盖结构问题。

## 4. 正式剧本格式

每集使用以下骨架：

```markdown
剧名：《<剧名>》
集数：EP-XX  <集标题>
模式：<模式>
对应剧情点：全季大纲 EP-XX
原著章节：原创项目，无原著
情绪类型：压力→行动→兑现→悬念
情绪强度：8/10
本集核心看点：<唯一的一句话>
本集资产引用：@资产A；@资产B

════════════════════════════════════════

场次 XX-1：内  <规范地点>  日
────────────────────────────────────────
出场人物：人物A；人物B

△（特写）可见、可表演、可生成的动作。

人物A
（表演指示）
短台词。

════════════════════════════════════════

【卡黑】

【台账登记块】
原著时间：上集结束时间锚=<...>｜本集原著时间原话=<...>｜事件先后=<...>｜闪回边界=<...>｜本集结束状态=<...>
【快照】
快照来源：EP-XX
- 末场原著时间锚/拍摄时段：<...>
- 地点：<末场规范地点>
- 在场人物：<...>
- 已完成事件：<...>
- 未了动作：<下一集必须接住的动作>
- 集尾钩子：<类型>·<唯一钩子>
【快照·完】
伏笔埋：<无或条目>
伏笔收：<无或条目>
道具：<状态/易主/证据>
角色状态：<角色｜变化｜证据>
场景名：<规范地点列表>
口径：<金额/期限/规则/行业事实>
行动线：<行动线｜阶段状态>
【台账登记块·完】
```

硬格式：

- `集数` 与文件名一致；标题与 `plot-map.md` 一致。
- 场次编号连续；场次头包含内/外、规范地点和时段。
- 台词采用“角色名 / 表演指示 / 台词”三行结构；台词尽量不超过25字，35字以上需拆句。
- 每个说话人和前景具名人物进入该场 `出场人物`。
- 动作行只写可见、可听、可表演的事实，不写“心想、意识到、浑然不觉”。
- 正文中的每个 `@资产` 必须进入全局视觉事实集合；头部 `本集资产引用` 至少列当集核心生成资产。若项目要求逐集完整预载，将 `require_body_assets_in_header` 设为 `true`。
- 只允许一个 `【卡黑】`，不写下集预告。

“有效正文长度”按第一条场次分隔线到 `【台账登记块】` 前的可见字符估算；头部元数据和台账不计入。时长最终仍以对白、动作节奏、停顿和转场复核，不迷信单一字数。

## 5. 连续性台账

### `plot-map.md`

逐集至少锁定：标题、压力/问题、主动行动、当集兑现、物质状态变化、尾钩。阶段表锁定外部目标、内部成长、对手和阶段出口。

### `character-cards.md`

每个主要角色记录：正式名、别名、年龄身份、外部目标、误区、弧光、声纹、核心关系、不可突破底线、状态资产和生效集。

### `ledger-foreshadow.md`

分别记录：

- 伏笔ID、埋设镜头、推进、回收要求、实际场次证据、状态。
- 信息初始持有者、获知路径、最早公开集、禁止越界。
- 道具首现、持有人、易主、损毁、终局。
- 金额、期限、订单、债务、赔偿和兑现集。

不能只把状态改成“已核销”；必须填实际场次或台词证据。

### `progress.md`

只由主编或主流程维护。记录已完成集、最新快照、各阶段状态、每集长度、校验结果、未解决问题和下一批入口。分集作者只提交集末台账，不直接改总进度。

## 6. 视觉事实格式

`visual-assets/source-facts.md` 建立全局实体表：

| 实体ID | 类型 | 剧本规范名 | 建议@资产名 | 别名 | 稳定外观/结构 | 状态 | 资产化决策 | 证据 |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|

ID前缀：

- `CHR-`：可见具名角色
- `VOC-`：不可见声音角色
- `SCN-`：物理场景
- `PRP-`：道具
- `GRP-`：无固定脸群像

状态资产使用 `@正式名_状态`，例如前期装、工作装、孕期装、损坏态、终局态。不同状态共用同一身份锚，不拆成不同人物。

逐集交接 `visual-assets/episodes/EP-XX.md` 至少包含：

```markdown
# EP-XX 视觉资产交接

schema_version: cn-shortdrama-visual-handoff/1.0
剧本路径：scripts/EP-XX.md
剧本SHA256：<64位小写哈希>
交接状态：READY

## 人物出现
## 场景出现
## 道具出现
## 未解决项
- 无
```

每条出现记录指向场次、实体ID、资产化决策、建议状态@和可见证据。`READY` 只表示剧本哈希匹配、实体均已解析、未解决项为无。

`visual-assets/handoff.md` 汇总全季每集剧本哈希、交接哈希和状态，并列出全局可用实体集合。

## 7. 分批创作与变更控制

推荐每批5至10集。每批入口包只包含：

- 当前权威版本的 `STORY-BIBLE.md`、`WRITING-SPEC.md`
- 当前阶段的 `plot-map.md` 行
- 相关人物卡、伏笔与信息权限
- 上一集末场快照
- 当前批的阶段出口

若环境允许且用户授权并行作者，分配互不重叠的集段；全局文件保持只读，由一个主编统一合并。并行不免除逐集衔接复核。

变更流程：

1. 记录变更原因和影响集。
2. 修改最高层权威源。
3. 同步剧情地图和台账。
4. 修改相关剧本。
5. 重跑机器校验和语义复核。
6. 刷新视觉交接哈希、资产出现集和交付清单。

不得直接手改最终合订本；合订本始终由单集源文件重新生成。
