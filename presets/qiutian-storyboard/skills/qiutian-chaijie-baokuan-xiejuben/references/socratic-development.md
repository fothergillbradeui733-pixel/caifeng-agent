## 1. 访谈目标

苏格拉底访谈不是收集偏好清单，而是和用户共同建立一套能支撑完整剧集的因果系统。每个关键决定都要回答：

- 它给观众什么具体期待？
- 它为什么只能由这个主角在此时面对？
- 它会导致哪些可见行动、损失、选择和升级？
- 它与已经锁定的设定是否一致？
- 它能否持续制造不同类型的冲突，而不是重复同一种打脸？
- 它怎样在中段接受反证，并在终局完成回收？

不预设固定题数。问题数量由不确定性和矛盾数量决定；复杂项目可以追问很多轮，简单项目也不能跳过完成门槛。“完全理解”指已经足以无任意补洞地进入项目圣经和全季大纲，不代表提前决定每句台词。

## 2. 访谈状态与决定来源

持续更新 `PROJECT-BRIEF.md`，不要只依赖对话记忆。每项决定只使用以下状态：

| 状态 | 含义 | 能否进入大纲 |
|:--|:--|:--|
| 待探索 | 尚未讨论，或只有类型标签 | 否 |
| 暂定 | 已有方向，但仍受其他答案影响 | 否 |
| 已锁定 | 已形成可执行决定，且通过冲突检查 | 是 |

同时标记决定来源：

- **用户确认**：用户明确选择或认可。
- **主创判断**：用户授权“你来定”后由主创决定。
- **文本事实**：来自用户提供的原作、样本或既有剧本。
- **有限推断**：依据不完整材料暂时得出，必须说明不确定性。

不得把主创补充写成用户原话。新答案推翻旧答案时，在决策日志记录变更原因和受影响文件，不保留两个互相冲突的版本。

续写旧项目时，若 `PROJECT-BRIEF.md` 缺少本协议要求的访谈状态、规则表或压力测试，不要假装已经通过。先从现有权威文件和已写剧本恢复决定，把缺少的章节迁入立项记录；能够由文本事实证明的直接补齐，真正影响后续走向的缺口再按一次一问处理。

## 3. 下一问选择算法

每轮先列出尚未锁定的候选变量，在内部评估四项：

1. **因果影响**：答案会改变多少人物、规则、阶段或结局？
2. **当前不确定性**：现有信息是否足以作出唯一合理判断？
3. **依赖数量**：有多少后续决定必须等它先确定？
4. **返工风险**：现在跳过，后面是否会推翻大量大纲？

优先询问综合影响最大的一个。不要严格照着题库机械轮询，也不要因为某个细节有趣就越过前置问题。

默认依赖顺序：

> 观看承诺 → 主角 → 开篇剥夺 → 外部欲望与内在误区 → 故事引擎 → 规则与代价 → 核心关系 → 反派资源 → 身份/事业阶梯 → 中段失败 → 终局回收 → 视觉气质与禁区

一个回合只能有一个待回答中心。可以先用一两句说明为什么需要问，但不要在同一句中塞入多个独立问题。带有“以及”“分别”“还有”的并列问句通常应拆轮。

## 4. 每轮回答处理

收到每个答案后，按顺序完成：

1. **捕捉意图**：保留用户真正重视的结果，不只摘关键词。
2. **具体化**：把“爽、惨、厉害、有代价”等标签翻译成可见事件或选择。
3. **推导影响**：判断它会改变主角、规则、关系、反派、阶段和终局中的哪些项。
4. **冲突检查**：对照全部已锁定决定，寻找逻辑、伦理、年代、能力和情绪承诺冲突。
5. **状态更新**：写入决定、来源、理由、状态和受影响项。
6. **选择下一问**：重新计算最高影响未决变量，不沿用预先写死的问题顺序。

以上处理默认在内部完成。只有在答案可能被误解、出现矛盾、需要做关键取舍或即将锁定阶段时，才向用户做简短复述；不要每轮都输出冗长总结。

常见回答的处理方式：

- **“没想法”**：给2至4个真正改变故事结构的方向，说明各自收益和代价，并推荐一个。
- **“都可以”**：根据已锁定的观看承诺主动选择最一致的方案，说明决定；除非该选择会改变用户明确禁区，否则不重复索要选择。
- **抽象标签**：追问它在第一集或关键场面中具体表现为什么可见损失、行动或结果。
- **答案互相冲突**：准确指出两项已确认事实，只问一个决定优先级或兼容方式的问题。
- **临时新增设定**：先判断它是补充、改写还是推翻，再更新最高层权威源。
- **“你来定/不要再问”**：切换自主模式，不停止思考，也不跳过检查。

## 5. 六层剧情探索

这些是必须覆盖的决策层，不是一次性发给用户的问题清单。

### 第一层：观看契约

锁定受众、平台、格式、集数、时长、类型、年代和核心情绪承诺。把“翻身打脸”进一步具体为观众要替谁追回什么、看见什么身份或物质变化。

解锁条件：能用一句话说清观众为什么点开、前5集必须兑现什么。

### 第二层：主角因果

锁定主角身份、已有能力、社会位置、开篇被夺走的具体事物、眼前目标、长期欲望、内在误区和不能退让的底线。

重点追问：为什么是他、为什么是现在、他过去做过什么导致今天、他不行动会失去什么、他主动选择什么而不是只挨打。

解锁条件：即使拿掉金手指，主角仍有明确欲望、行动能力和人格缺陷。

### 第三层：故事引擎

锁定功能、触发、输入输出、反馈、代价、禁区、错误后果、知识边界、升级次数和终局退出。规则必须能通过场面验证，也必须允许失败或被利用。

重点追问：第一次触发为何发生、主角怎样排除巧合、错误输入会怎样、对手知道后能做什么、能力为什么不能一次解决终局。

解锁条件：能写出至少一次成功验证、一次误用失败和一次规则升级，三者因果不同。

### 第四层：关系与对抗

锁定核心盟友的独立目标、能力、资源、否决权和关系边界；锁定家人或反派的具体利益、有效手段、可升级资源及失败原因。

重点追问：盟友何时会反对主角、反派为什么不直接离场、和解需要哪些可见代价、主角救急与无条件兜底的边界在哪里。

解锁条件：重要人物不只是功能件；每个阶段对手都迫使主角获得一种新能力。

### 第五层：全季升级

锁定生存、立足、建制、团队、自主事业和终局规则战的状态变化；明确前5集承诺、中段最大失败、修复成本和终局证据链。

重点追问：每10集什么发生不可逆变化、一次胜利怎样产生更大责任、若删除一个阶段会丢失什么因果、主角最后靠什么不再依赖奇遇。

解锁条件：全季不是重复获利或重复羞辱；中段失败由主角选择造成，并改变其做事原则。

### 第六层：表达边界

锁定年代与行业真实感、视觉质感、冲突尺度、价值底线、内容禁区、AI制作约束和原创隔离边界。

重点追问：哪些内容绝对不能出现、哪些夸张可以接受、哪些参考机制可以迁移但哪些标志性组合必须避开。

解锁条件：创作团队知道“可以怎么大胆”和“绝对不能怎么写”。

## 6. 深挖方法与问题质量

根据缺口选择方法，不要连续只问“为什么”：

- **具体化**：这个词在镜头里表现成什么动作、损失或证据？
- **两难取舍**：两个目标冲突时，主角先保哪一个？失去什么？
- **边界探测**：做到什么程度就不再是帮助，而是纵容或越界？
- **反事实**：如果没有奇遇、盟友或这条规则，主角还会怎么行动？
- **最坏案例**：这项能力被误用、复制或公开后，最严重但合理的后果是什么？
- **对手视角**：一个理性对手为什么必须阻止主角，他会先动用什么资源？
- **时间推进**：这个决定在第1、10、30、60集分别产生什么状态变化？
- **回收追问**：开篇的伤害、物件、誓言或错误信念最终怎样被行动重新定义？

高质量问题满足四点：只决定一个中心变量；答案会改变后续结构；用户能够依据偏好或经验回答；没有暗示唯一正确答案。

低质量问题包括：纯装饰细节、可以稍后由主创无风险决定的内容、换词不换结构的选项、已经回答过的问题、在一个问号前塞进多项调查。

## 7. 设定压力测试

在停止提问前，把结论写入 `PROJECT-BRIEF.md`，每项给出具体证据，不能只写“没问题”。

| 测试 | 必须证明 |
|:--|:--|
| 欲望独立性 | 没有金手指，主角仍会为同一核心欲望行动 |
| 因果必要性 | “这个人、这个时刻、这次剥夺、这次触发”构成闭环 |
| 引擎边界 | 能力有验证方式、失败方式、被利用风险和知识盲区 |
| 关系能动性 | 核心盟友有独立利益和至少一次有效否决或纠偏 |
| 理性反派 | 对手拥有真实利益与资源，失败后会学习或升级 |
| 全季承载力 | 各阶段改变身份、资产、规则或关系，不能任意删段 |
| 中段反证 | 主角长处过量使用导致失败，并承担修复成本 |
| 终局回收 | 开篇剥夺、内在误区、核心规则和关系贡献均有回收 |
| 原创隔离 | 只迁移抽象机制，不复刻样本的专名、组合和事件顺序 |

任何一项未通过，都回到对应决策层继续追问或自主补全；不得用“后面写的时候再说”越过立项门。

## 8. 立项完成门槛

只有同时满足以下条件才停止访谈并进入大纲：

- `PROJECT-BRIEF.md` 的必备决定全部为“已锁定”。
- 每项决定都有具体内容、来源和理由，不只有类型标签。
- 阻塞未决项为零；已知矛盾为零。
- 一句话故事同时包含人物、剥夺、机会、行动和终局变化。
- 前5集承诺、中段最大失败、全季升级阶梯和终局回收可以互相解释。
- 故事引擎规则可以用成功、失败和升级三个不同场面验证。
- 核心关系和每级反派都拥有独立利益与行动资源。
- 九项设定压力测试全部有证据并通过。
- `validate_brief.py` 返回 `BRIEF-PASS`。

校验脚本只能证明结构完整，不能代替主创判断。即使脚本通过，只要某项仍无法转化成动作、冲突或状态变化，也要继续讨论。

## 9. 自主决策模式

用户授权自主决定后，按相同顺序在内部自问自答：

1. 列出剩余未锁定项。
2. 每项生成2至4种有实质差异的方案。
3. 按观看承诺、因果强度、全季承载力和原创距离选择。
4. 在 `PROJECT-BRIEF.md` 将来源写为“主创判断”，记录取舍理由。
5. 运行全部压力测试和立项校验。

自主模式减少对用户的打扰，不降低设定深度。遇到会改变用户明确禁区、交付规格或核心价值方向的冲突时，才重新请求用户决定。

## 10. 共识回放与交接

互动访谈完成后，用简洁语言向用户回放：

1. 这是谁的故事，他开局被夺走什么。
2. 观众主要追哪几本账，前5集先兑现什么。
3. 故事引擎怎样工作、怎样失败、怎样升级。
4. 核心关系为什么会并肩，也会因为什么发生有效冲突。
5. 阶段对手如何升级，中段为何失败。
6. 终局怎样回收开篇和主角内在误区。
7. 哪些内容是用户确认，哪些是主创判断。

仍处于互动模式时，回放后只问一个问题：“以上哪一点最需要纠正？”用户确认无误后锁定；用户已说不再提问时，直接把回放写入立项记录并进入项目圣经。
